# Backlog 수집 (스킬 1)

사용자가 시킨 일·기능·개선 아이디어를 **삭제하지 않고** `Backlog.md`에 누적한다.
구현을 바로 시작하라는 명시가 없으면, 이 스킬로 백로그에만 남기고 짧게 확인한다.

## 파일 위치

- 경로: 레포 루트 `Backlog.md` (없으면 아래 템플릿으로 생성)
- 다른 경로에 쓰지 않는다.

## 언제 쓰는가

- 「백로그에 넣어 줘」「Backlog에 쌓아」「나중에 할 일로 남겨」
- 여러 요청을 나열했지만 「지금은 구현하지 말고 목록만」인 경우
- 구현 중에 「이것도 나중에」로 빠진 항목을 놓치지 않게 할 때

## 수집 규칙

1. **추가만 한다.** 기존 항목을 지우거나 「완료」로 임의 처리하지 않는다. (완료·로드맵 이관은 다른 스킬)
2. **한 요청 = 한 항목.** 사용자가 한 메시지에 여러 일을 나열하면 항목을 나눠 각각 bullet로 넣는다.
3. **원문 보존 + 최소 맥락.** 사용자 표현을 유지하되, 모호하면 한 줄로 맥락(어느 화면/대상인지)을 덧붙인다. 추측으로 범위를 좁히지 않는다.
4. **날짜 스탬프.** 새로 넣는 항목에는 수집일 `YYMMDD`를  squashed 표기한다.
5. **중복.** 거의 같은 요청이 이미 있으면 새 bullet을 만들지 말고, 기존 항목 아래에 `- (추가 YYMMDD) …`로 보강한다.
6. **구현과 분리.** 이 스킬만 호출된 경우 코드 변경·PR을 하지 않는다. `Backlog.md`만 갱신한다.

## Backlog.md 템플릿 (없을 때)

```markdown
# Backlog

Memory of Records — 요청·아이디어 누적 목록.
우선순위·로드맵 이관은 `backlog-to-roadmap` 스킬, 정리·그룹핑은 `backlog-enrich` 스킬을 쓴다.

## Inbox

<!-- 새 요청은 이 섹션 맨 위에 쌓는다 (최신순) -->

```

## 항목 형식

```markdown
- [ ] **짧은 제목** `(수집 YYMMDD)`
  - 요청 요지: …
  - 맥락/화면: … (알면)
  - 원문 메모: 「…」
```

## 작업 절차

1. `Backlog.md`가 없으면 템플릿으로 생성한다.
2. 사용자 메시지에서 할 일 단위를 분리한다.
3. `## Inbox` **맨 위**에 새 항목을 추가한다 (최신이 위로).
4. 사용자에게 추가된 제목 목록만 짧게 알려 준다. 「다음에 enrich / 우선순위 잡을까요?」정도만 제안한다.

## 하지 말 것

- Inbox 항목을 멋대로 Roadmap으로 옮기기
- 문장을 예쁘게 줄이느라 요구사항을 삭제하기
- 백로그만 하라고 했는데 구현 시작하기
